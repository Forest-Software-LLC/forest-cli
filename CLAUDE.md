# forest-cli

The `forest` command-line package manager for **forestpm** (Roblox + UEFN/Verse packages). Rust, built on `clap` (CLI), `tokio` (async), `reqwest` (HTTP).

> Part of the forestpm ecosystem. Full map + API details in `../forest-backend/CLAUDE.md`. This binary is a client of that API. Platform-seam design (how roblox/ and uefn/ stay isolated) is in [ARCHITECTURE.md](ARCHITECTURE.md).

## Key modules
- [src/platform.rs](src/platform.rs) — the platform seam: every platform-divergent behavior goes through the `Platform` enum, delegating into [src/roblox/](src/roblox/) or [src/uefn/](src/uefn/). Dependency rule: core modules (solver, lockfile, http, cache, receipts, fetch) never import platform code; platform modules import core, never each other. See [ARCHITECTURE.md](ARCHITECTURE.md).
- [src/contracts.rs](src/contracts.rs) — loaders for the `shared/` git submodule (forest-shared-resources): `shared/contracts/*.json` is the single source of truth for platform rules + license knowledge across backend/gateway/CLI. Vectors files are asserted in unit tests so a submodule bump that changes behavior fails the build.
- [src/http.rs](src/http.rs) — API client wrapper. Shared `OnceLock` clients (keep-alive + timeouts): async for API calls, blocking for tarball downloads (gzip OFF there — transparent decompression would break integrity hashing).
- [src/tokens.rs](src/tokens.rs) — auth-token storage (home dir via the `dirs` crate).
- [src/commands/context.rs](src/commands/context.rs) — `load_project()`: the shared command preamble (manifest discovery + chdir + parse + platform). Every project-scoped command starts here; don't hand-roll the discover-then-read dance in a new command.
- [src/lockfile_gen.rs](src/lockfile_gen.rs) + [src/lockfile_solver.rs](src/lockfile_solver.rs) — dependency resolution (`semver`) + install execution. Version lists prefetch concurrently (lowercased URLs + `?detail=install`: the fat response inlines install metadata for the version frontier, so most versions resolve with no second request); the BFS awaits memoized handles at the original points, so lockfiles stay deterministic. Off-frontier picks fall through the metadata disk cache, then a per-version gateway fetch. A range no cached list satisfies triggers ONE `__fresh` cache-busted refetch of that list (publish → install of a brand-new version works even before the backend's edge purge lands). Downloads run through [src/download_pool.rs](src/download_pool.rs): one bounded 8-worker pool + private signed-URL prefetch shared by both platform executors, which pass in only a job list and an extract+receipt closure.
- [src/meta_cache.rs](src/meta_cache.rs) — per-version metadata disk cache (`~/.forest/cache/meta/`; same `FOREST_CACHE_DIR`/`FOREST_NO_CACHE` knobs). **Accelerator, never an authority**: entries supply resolution data (deps, integrity), so every entry consumed from disk is re-fetched in one concurrent confirmation pass before a lockfile is written — mismatch ⇒ evict + warn + cacheless re-resolve. Invariant: every hash in a fresh lockfile arrived from the registry over TLS that session. `install --force` skips cache reads; `pending` license ratings are never stored (they settle seconds after publish and would mismatch spuriously).
- [src/roblox/plan.rs](src/roblox/plan.rs) — pure path/pointer planning (no IO); layout pinned by unit tests. Plan paths stay in the virtual `./Packages/...` format; the physical mount (`packages_base` in [src/roblox/mod.rs](src/roblox/mod.rs): `<parent-of-root>/Packages`, e.g. `src/Packages` for root `src/init.luau`) is applied only at execution points in [src/roblox/install.rs](src/roblox/install.rs).
- [src/roblox/install.rs](src/roblox/install.rs) — **rojo-safe mount mutation**: a live `rojo serve` (7.7.0) panics on watcher events whose paths no longer resolve, so the mount only ever sees whole-unit renames. Deletions rename dirs into a trash bin (parents first — one event per unit; hard-retried, since a re-snapshotting watcher holds child handles) and deletion happens there; installs extract + assemble each top-level unit in a staging area (nested deps, pointers, receipts, and the type-link pass via `relink_types_staged`) then rename it in atomically. Both scratch dirs live in the system temp dir when same-volume (rojo watches the whole project root recursively — project-local scratch leaks re-keyed events), else `.forest-trash`/`.forest-staging` next to forest.json (swept on the next run). `settle_watchers`: when forest-lock.json is <3s old AND a rojo answers on `servePort`/34872, wait out the remainder so the watcher drains the previous run's events before the mount changes again (margin, not load-bearing — the bench passes with it disabled); `FOREST_NO_SETTLE=1` skips. Validated by [scripts/rojo-bench.ps1](scripts/rojo-bench.ps1) install/remove/force/rapid-cycle scenarios against a live rojo + emulated Studio subscriber.
- [src/receipts.rs](src/receipts.rs) — incremental installs with **zero files outside `Packages/`**: each installed dir carries a `.forest-receipt` (extension-less ⇒ Rojo-ignored, like LICENSE) written after its extraction succeeds. Receipt read/write + the flat tree taxonomy live here; the recursive Roblox scan/reconcile (pointer dirs recognized by their generated init.lua header) is [src/roblox/receipts.rs](src/roblox/receipts.rs). Install = scan tree → reconcile vs plan: matching `(integrity, root)` receipts are kept, stale forest-managed dirs deleted, receipt-less dirs never trusted (covers crashes, branch switches, pre-receipt trees). Nested packages can't be kept when an ancestor reinstalls. `--force` ignores all receipts.
- [src/cache.rs](src/cache.rs) — content-addressed tarball cache at `~/.forest/cache/<sha256>.tgz` (re-verified on every read; corrupt ⇒ delete + redownload). `FOREST_CACHE_DIR` overrides, `FOREST_NO_CACHE=1` disables. Private packages are cached too (hash is the trust anchor; access enforced at first download).
- [src/fetch_and_extract.rs](src/fetch_and_extract.rs) — cache lookup → download → sha256 verify → unpack (`tar` + `flate2`).
- [src/uefn/](src/uefn/) — UEFN (Verse) platform: project discovery, scope → Verse-identifier mapping, marker-file generation (delete-by-header only), running-editor probe, root-definition lint. Layout/marker semantics documented in forest-backend `docs/uefn-adapter.md`.
- [src/links.rs](src/links.rs) + [src/roblox/link_overlay.rs](src/roblox/link_overlay.rs) — `forest link`. Core module: `.forest/links.json` storage (unknown-field-preserving), policy (install's `--links apply|ignore|forbid`; default ignore under CI, apply otherwise), matching stored links to direct deps, the stderr banner. Roblox overlay: resolution/lockfile run on the pure registry graph, then each linked slot (`<mount>/<Alias>`) is OPAQUE to reconcile/prune/pointer-writes/type-relink (nothing is ever written or deleted through it) and finally materialized as a junction (Windows)/symlink to the linked manifest's root-parent dir — or a copy when link creation fails or the root module isn't init-named (copy applies the extraction rename). A linked package's own deps come from ITS working tree (`<root-parent>/<packagesDir>` rides along inside the slot), never from this project's graph; drift vs the pinned registry version is reported, not resolved. `publish` hard-refuses while a dep of the published manifest is linked.
- [src/roblox/wally.rs](src/roblox/wally.rs) — wally.toml → forest.json dependency conversion (wally packages are mirrored on the registry under the same `scope/name`; bare versions gain `^`).
- [src/release_verify.rs](src/release_verify.rs) — pinned-key verification of the offline-signed release manifest (`ssh-keygen -Y sign -n forest-release`); `forest update` refuses unverified manifests.
- [src/license_helper.rs](src/license_helper.rs), [src/message.rs](src/message.rs), [src/utils.rs](src/utils.rs).

## Package manifest — `forest.json`
```json
{ "name": "orgtest", "author": "org1", "version": "0.1.1",
  "platform": "roblox", "description": "...", "dependencies": {} }
```
`platform` is `"roblox"` or `"uefn"`. `.forestignore` controls what `publish` excludes. Two optional constraint maps, both `"scope/name": "<range>"`: `overrides` forces every transitive edge to that package onto the range (the range REPLACES what parents declared); `excludes` bans the matching versions outright for direct + transitive deps alike (declared ranges still honored minus the banned set). Both apply only to the declaring project (publish warns, the gateway schema strips them) and are recorded verbatim in forest-lock.json so drift invalidates the lockfile.

## Config / endpoints
[src/main.rs](src/main.rs) sets env vars at startup via a live `ENV=dev` switch — **prod is the default**:
- prod: `FOREST_API_URL=https://api.forest.dev/`, `FOREST_PACKAGES_URL=https://packages.forest.dev/` (trust gateway), `FRONTEND_URL=https://forest.dev/`; tarball CDN `https://registry.forest.dev` (`FOREST_CDN_BASE` overrides, [src/lockfile_gen.rs](src/lockfile_gen.rs)).
- `ENV=dev`: localhost `3001` (API) / `8081` (gateway) / `3000` (frontend). The backend's `.env` pins port **3001** for local runs, so dev lines up out of the box.

Install-related env knobs: `FOREST_CACHE_DIR`, `FOREST_NO_CACHE=1`, `FOREST_NO_UPDATE_CHECK=1` (used by [scripts/bench.ps1](scripts/bench.ps1)), `FOREST_NO_SETTLE=1` (skip the rojo settle wait).

## Build / release
```bash
cargo build --release      # target/release/forest(.exe)
```
**Release pipeline lives in this repo:** [.github/workflows/release.yml](.github/workflows/release.yml) (on `v*.*.*` tags) builds four targets — win x64, linux x64, mac arm64 + x64 — then [scripts/release.ts](scripts/release.ts) publishes to R2 under `cli/<tag>/` + `cli/latest/` (binaries named `forest-<tag>-<target>[.exe]`, plus `.sha256` sidecars, `SHA256SUMS`, and a `latest.json` manifest). Public CDN: `https://releases.forest.dev`.

**Distribution channels** (consumers of those artifacts):
- **cli-script-installer** repo (primary): `curl -fsSL https://releases.forest.dev/install.sh | sh` / `irm https://releases.forest.dev/install.ps1 | iex`. Both scripts verify the manifest's offline release signature with the same keys [src/release_verify.rs](src/release_verify.rs) pins — a key rotation must update both repos.
- **cli-installer** repo: Slint GUI wizard
- The old Inno Setup installer (`forest_installer.iss`) was removed in July 2026 — the script + GUI installers replaced it.

## Benchmarks
[scripts/bench.ps1](scripts/bench.ps1) times `install` against prod (fixture of real Wally-mirror packages). `-SetupFixture` once, then `-Exe <binary> -Label <name>`; scenarios: cold / reinstall / warmcache / resolve. Results CSV lands in `-BenchRoot`.

[scripts/rojo-bench.ps1](scripts/rojo-bench.ps1) proves install/remove/force/update/rapid-cycle sequences never crash a live `rojo serve` (downloads Rojo itself; emulated Studio client subscribed over Rojo's WebSocket API; exits 1 if rojo dies). Run it whenever mount mutation logic in [src/roblox/install.rs](src/roblox/install.rs) changes — the crash class it guards against (Rojo unwrap-panics on watcher events whose paths no longer resolve) is invisible to unit tests.

## Gotchas
- Install state lives ONLY inside the Packages mount (per-dir `.forest-receipt` files) — nothing is written to the project root besides forest.json/forest-lock.json. Deleting a package dir deletes its receipt with it; `install --force` reinstalls everything.
- The mount's location follows forest.json's `root`: manifests with a nested root (package authoring) install to `<root-parent>/Packages`; root-less manifests (projects) keep `./Packages`. forest-lock.json always stays at the manifest dir.
- Mount entries starting with `_` or `.` are never touched (Wally `_Index` coexistence).
- Symlinked/junction dirs in the mount are never descended into or deleted-through: the receipt scan and type-relink walk skip them, prune and slot-clearing remove the LINK only (`link_overlay::remove_slot`/`remove_link_path`). This protects `forest link` targets (real source trees) from install machinery.
