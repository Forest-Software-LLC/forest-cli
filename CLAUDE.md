# forest-cli

The `forest` command-line package manager for **forestpm** (Roblox + UEFN/Verse packages). Rust, built on `clap` (CLI), `tokio` (async), `reqwest` (HTTP).

> Part of the forestpm ecosystem. Full map + API details in `../forest-backend/CLAUDE.md`. This binary is a client of that API. Platform-seam design (how roblox/ and uefn/ stay isolated) is in [ARCHITECTURE.md](ARCHITECTURE.md).

## Key modules
- [src/platform.rs](src/platform.rs) — the platform seam: every platform-divergent behavior goes through the `Platform` enum, delegating into [src/roblox/](src/roblox/) or [src/uefn/](src/uefn/). Dependency rule: core modules (solver, lockfile, http, cache, receipts, fetch) never import platform code; platform modules import core, never each other. See [ARCHITECTURE.md](ARCHITECTURE.md).
- [src/contracts.rs](src/contracts.rs) — loaders for the `shared/` git submodule (forest-shared-resources): `shared/contracts/*.json` is the single source of truth for platform rules + license knowledge across backend/gateway/CLI. Vectors files are asserted in unit tests so a submodule bump that changes behavior fails the build.
- [src/http.rs](src/http.rs) — API client wrapper. Shared `OnceLock` clients (keep-alive + timeouts): async for API calls, blocking for tarball downloads (gzip OFF there — transparent decompression would break integrity hashing).
- [src/tokens.rs](src/tokens.rs) — auth-token storage (home dir via the `dirs` crate).
- [src/commands/context.rs](src/commands/context.rs) — `load_project()`: the shared command preamble (manifest discovery + chdir + parse + platform). Every project-scoped command starts here; don't hand-roll the discover-then-read dance in a new command.
- [src/mounts.rs](src/mounts.rs) - a project's mounts: the default one (top-level `dependencies`, placed by the platform: Roblox `<root-parent>/<packagesDir>`) plus extra ones under `mounts`, keyed by path. Parses and validates them as a set (folder-name rule on each name, no two equal or nested, none holding the root file; a bad `mounts` field fails every command loudly), resolves `--mount` references, and is the only writer of the `mounts` field. Also home of `validate_folder_name`, the dependency-folder rule `packagesDir` shares.
- [src/lockfile.rs](src/lockfile.rs) - the forest-lock.json format. The default mount's `LockSection` stays at the top level (the shape older CLIs read); every other mount's lives under `mounts`, skipped when empty, so single-mount lockfiles are byte-identical to pre-mount ones (pinned by a test). Each section records the overrides/excludes it was solved under, so one mount can resolve while the others carry over.
- [src/lockfile_gen.rs](src/lockfile_gen.rs) + [src/lockfile_solver.rs](src/lockfile_solver.rs) - install orchestration + dependency resolution (`semver`). `sync` decides per mount whether its section still satisfies forest.json (kept) or must resolve (stale, or asked for via `Refresh`), merges the solver reports across mounts (an override is unused only if no mount reached it), installs each mount through `Platform::install`, drops sections for mounts no longer declared (full runs only, with a warning), and is the only writer of forest-lock.json. Version lists prefetch concurrently (lowercased URLs + `?detail=install`: the fat response inlines install metadata for the version frontier, so most versions resolve with no second request); the BFS awaits memoized handles at the original points, so lockfiles stay deterministic. Off-frontier picks fall through the metadata disk cache, then a per-version gateway fetch. A range no cached list satisfies triggers ONE `__fresh` cache-busted refetch of that list (publish → install of a brand-new version works even before the backend's edge purge lands). Solver state is one entry per CANONICAL package (`ResolvedPackages`): a package reached under an old address in one manifest and its current one in another shares buckets and gets one lockfile entry. Downloads run through [src/download_pool.rs](src/download_pool.rs): one bounded 8-worker pool + private signed-URL prefetch shared by both platform executors, which pass in only a job list and an extract+receipt closure.
- [src/renames.rs](src/renames.rs) - a package reached under an old address (claimed scope or registry rename; the registry answers with the canonical scope/name). The resolve rewrites forest.json to the canonical key and re-keys the roots; `install <old address>` writes the canonical key directly. A new scope or casing lets a defaulted install folder follow the canonical name; a new package NAME writes the old name as an explicit alias (`kept_alias`) so requires keep working. A declared alias is never touched.
- [src/meta_cache.rs](src/meta_cache.rs) - per-version metadata disk cache (`~/.forest/cache/meta/`; same `FOREST_CACHE_DIR`/`FOREST_NO_CACHE` knobs). **Accelerator, never an authority**: entries supply resolution data (deps, integrity), so every entry consumed from disk is re-fetched in one concurrent confirmation pass before a lockfile is written - mismatch ⇒ evict + warn + cacheless re-resolve. Invariant: every hash in a fresh lockfile arrived from the registry over TLS that session, with one exception: a private package the registry refuses (401/404) is carried verbatim from the previous forest-lock.json (`LockedPrivate` in [src/lockfile_solver.rs](src/lockfile_solver.rs), deps pinned `=x.y.z`), since the caller can't read it to re-confirm. They can't download it either; an authorized teammate's install re-checks the hash against the registry in `fetch_signed_url`. `install --force` skips cache reads; `pending` license ratings are never stored (they settle seconds after publish and would mismatch spuriously).
- [src/roblox/plan.rs](src/roblox/plan.rs) - pure path/pointer planning (no IO); layout pinned by unit tests. Plan paths stay in the virtual `./<mount name>/...` format; the physical mount path (the default one is `packages_base` in [src/roblox/mod.rs](src/roblox/mod.rs): `<parent-of-root>/Packages`, e.g. `src/Packages` for root `src/init.luau`) is applied only at execution points in [src/roblox/install.rs](src/roblox/install.rs). Pointers never climb above their mount, so a mount can be renamed without reinstalling.
- [src/roblox/install.rs](src/roblox/install.rs) + [src/roblox/scratch.rs](src/roblox/scratch.rs) - **rojo-safe mount mutation**: a live `rojo serve` (7.7.0) panics on watcher events whose paths no longer resolve, so the mount only ever sees whole-unit renames. Deletions rename dirs into a trash bin (parents first - one event per unit; hard-retried, since a re-snapshotting watcher holds child handles) and deletion happens there; installs extract + assemble each top-level unit in a staging area (nested deps, pointers, receipts, and the type-link pass via `relink_types_staged`) then rename it in atomically. `TrashBin`/`StagingArea`/`scratch_dirs` live in scratch.rs and are also used by the link overlay: `remove_slot` trashes real dirs but removes junction slots as LINKS. Both scratch dirs live in the system temp dir when same-volume (rojo watches the whole project root recursively - project-local scratch leaks re-keyed events), else `.forest-trash`/`.forest-staging` next to forest.json (swept on the next run). `settle_watchers`: when forest-lock.json is <3s old AND a rojo answers on `servePort`/34872, wait out the remainder so the watcher drains the previous run's events before the mount changes again (margin, not load-bearing - the bench passes with it disabled); `FOREST_NO_SETTLE=1` skips. Validated by [scripts/rojo-bench.ps1](scripts/rojo-bench.ps1) install/remove/force/rapid-cycle scenarios against a live rojo + emulated Studio subscriber (single mount, then several: Wally takeover, mount rename/remove, rapid cycles), plus a link-composition smoke (link/force/CI-ignore/unlink, and a link inside a second mount that is then removed, under a live rojo). The executor runs once per mount; the abandoned-folder check runs once per install across all of them (`Platform::check_mounts`). [src/roblox/mount_dirs.rs](src/roblox/mount_dirs.rs) does `forest mount`'s whole-folder remove/move (one rename each, link slots removed as links first) and the foreign-files check `mount create` uses.
- [src/receipts.rs](src/receipts.rs) — incremental installs with **zero files outside `Packages/`**: each installed dir carries a `.forest-receipt` (extension-less ⇒ Rojo-ignored, like LICENSE) written after its extraction succeeds. Receipt read/write + the flat tree taxonomy live here; the recursive Roblox scan/reconcile (pointer dirs recognized by their generated init.lua header) is [src/roblox/receipts.rs](src/roblox/receipts.rs). Install = scan tree → reconcile vs plan: matching `(integrity, root)` receipts are kept, stale forest-managed dirs deleted, receipt-less dirs never trusted (covers crashes, branch switches, pre-receipt trees). Nested packages can't be kept when an ancestor reinstalls. `--force` ignores all receipts.
- [src/cache.rs](src/cache.rs) — content-addressed tarball cache at `~/.forest/cache/<sha256>.tgz` (re-verified on every read; corrupt ⇒ delete + redownload). `FOREST_CACHE_DIR` overrides, `FOREST_NO_CACHE=1` disables. Private packages are cached too (hash is the trust anchor; access enforced at first download).
- [src/fetch_and_extract.rs](src/fetch_and_extract.rs) — cache lookup → download → sha256 verify → unpack (`tar` + `flate2`).
- [src/uefn/](src/uefn/) — UEFN (Verse) platform: project discovery, scope → Verse-identifier mapping, marker-file generation (delete-by-header only), running-editor probe, root-definition lint. Layout/marker semantics documented in forest-backend `docs/uefn-adapter.md`.
- [src/links.rs](src/links.rs) + [src/roblox/link_overlay.rs](src/roblox/link_overlay.rs) - `forest link`. Core module: `.forest/links.json` storage (unknown-field-preserving), policy (install's `--links apply|ignore|forbid`; default ignore under CI, apply otherwise), matching stored links to direct deps, the stderr banner. Roblox overlay: resolution/lockfile run on the pure registry graph, then each linked slot (`<mount>/<Alias>`) is OPAQUE to reconcile/prune/pointer-writes/type-relink (nothing is ever written or deleted through it) and finally materialized as a junction (Windows)/symlink to the linked manifest's root-parent dir - or a copy when link creation fails or the root module isn't init-named (copy applies the extraction rename). A linked package's own deps come from ITS working tree (`<root-parent>/<packagesDir>` rides along inside the slot), never from this project's graph; drift vs the pinned registry version is reported, not resolved. `publish` hard-refuses while a dep of the published (default) mount is linked. Links for the default mount live under `links` (all older CLIs read); links for other mounts live under `mounts.<path>`, which older CLIs never see. A full install drops links into a folder that is no longer a mount (its junctions removed as links first), and `unlink --mount` accepts such a folder too.
- [src/roblox/wally.rs](src/roblox/wally.rs) - wally.toml -> forest.json dependency conversion (wally packages are mirrored on the registry under the same `scope/name`; bare versions gain `^`). `[dependencies]` go to the default mount, `[server-dependencies]` and `[dev-dependencies]` to `ServerPackages`/`DevPackages` mounts (Wally's own folders, so Rojo mappings keep working); `init` deletes wally.lock.
- [src/release_verify.rs](src/release_verify.rs) — pinned-key verification of the offline-signed release manifest (`ssh-keygen -Y sign -n forest-release`); `forest update` refuses unverified manifests.
- [src/message.rs](src/message.rs) - output helpers and the one error look: `fail`, the error `main` prints (any `Err` a command returns, causes included), and the skipped-packages report all render as a bold red headline (the text's first sentence) with everything else as plain paragraphs indented under it, word-wrapped to the terminal (max 100 columns, unwrapped when piped). So write errors as "What failed. What to do about it." and prefer returning `Err` over printing `fail` and returning `Ok`: failures must exit 1.
- [src/license_helper.rs](src/license_helper.rs), [src/utils.rs](src/utils.rs), [src/ci.rs](src/ci.rs) (the only `CI` env check; `CI=false`/`0` count as off).

## Package manifest — `forest.json`
```json
{ "name": "orgtest", "author": "org1", "version": "0.1.1",
  "platform": "roblox", "description": "...", "dependencies": {} }
```
`platform` is `"roblox"` or `"uefn"`. `.forestignore` controls what `publish` excludes. Optional `visibility` (`"public"`/`"private"`) is read only by publish: it settles a new package's visibility without the prompt, and must match an existing package's (a publish never changes visibility; the gateway strips the field). Two optional constraint maps, both `"scope/name": "<range>"`: `overrides` forces every transitive edge to that package onto the range (the range REPLACES what parents declared); `excludes` bans the matching versions outright for direct + transitive deps alike (declared ranges still honored minus the banned set). Both apply only to the declaring project (publish warns, the gateway schema strips them) and are recorded verbatim in forest-lock.json so drift invalidates the lockfile. They are project-wide: every mount resolves under them.

Optional `mounts` (Roblox only) declares extra dependency folders, each resolved and installed on its own and never sharing packages: `"mounts": { "src/server/Packages": { "dependencies": { ... } } }`, keyed by path relative to forest.json, same dependency syntax as the top level. Only the default mount (top-level `dependencies`) is published; publish warns about the rest, force-excludes every mount from the tarball (literal, case-insensitive path match, so a key that differs in case from its folder still can't ship), and the gateway strips the field.

## Config / endpoints
[src/main.rs](src/main.rs) sets env vars at startup via a live `ENV=dev` switch — **prod is the default**:
- prod: `FOREST_API_URL=https://api.forest.dev/`, `FOREST_PACKAGES_URL=https://packages.forest.dev/` (trust gateway), `FRONTEND_URL=https://forest.dev/`; tarball CDN `https://registry.forest.dev` (`FOREST_CDN_BASE` overrides, [src/lockfile_gen.rs](src/lockfile_gen.rs)).
- `ENV=dev`: localhost `3001` (API) / `8081` (gateway) / `3000` (frontend). The backend's `.env` pins port **3001** for local runs, so dev lines up out of the box.

Install-related env knobs: `FOREST_CACHE_DIR`, `FOREST_NO_CACHE=1`, `FOREST_NO_UPDATE_CHECK=1` (used by [scripts/bench.ps1](scripts/bench.ps1)), `FOREST_NO_SETTLE=1` (skip the rojo settle wait).

`FOREST_TOKEN` ([src/api_token.rs](src/api_token.rs)): a read-only API token for CI. Wins over `~/.forest_tokens.json` (which is then never read), never refreshed; a 401 with it set is a hard error naming the server's reason. `whoami` describes it via `GET v1/auth/token`, `publish` refuses to run with it. A private package the registry refuses at download time (no credential, expired login, or a 404 for a scope the caller can't read) is skipped, not fatal: the rest of the tree installs, then main prints one error listing the skipped packages + failed scopes and exits 1 ([src/install_report.rs](src/install_report.rs); the Roblox executor also drops everything nested under a skipped slot). Resolution has the same policy: when a re-resolve (adding a package, `remove`, `update`, an edited forest.json) gets 401/404 for a package the current lockfile marks private, it keeps that package's lockfile pins and warns instead of failing (a range the pins don't satisfy is still an error); the warning says whether to log in (no login, or a rejected one) or ask for access. Registry 404s everywhere carry `message::PRIVATE_404_HINT`. `install --frozen` errors instead of re-resolving when forest-lock.json is missing or no longer satisfies forest.json.

## Build / release
```bash
cargo build --release      # target/release/forest(.exe)
```
**Release pipeline lives in this repo:** [.github/workflows/release.yml](.github/workflows/release.yml) (on `v*.*.*` tags) builds four targets — win x64, linux x64, mac arm64 + x64 — then [scripts/release.ts](scripts/release.ts) publishes to R2 under `cli/<tag>/` + `cli/latest/` (binaries named `forest-<tag>-<target>[.exe]`, plus `.sha256` sidecars, `SHA256SUMS`, and a `latest.json` manifest). Public CDN: `https://releases.forest.dev`.

**Distribution channels** (consumers of those artifacts):
- **cli-script-installer** repo (primary): `curl -fsSL https://releases.forest.dev/install.sh | sh` / `irm https://releases.forest.dev/install.ps1 | iex`. Both scripts verify the manifest's offline release signature with the same keys [src/release_verify.rs](src/release_verify.rs) pins — a key rotation must update both repos.
- **cli-installer** repo: Slint GUI wizard
- The old Inno Setup installer (`forest_installer.iss`) was removed in July 2026 — the script + GUI installers replaced it.

## Benchmarks
[scripts/bench.ps1](scripts/bench.ps1) times `install` against prod (fixture of real Wally-mirror packages). `-SetupFixture` once, then `-Exe <binary> -Label <name>`; scenarios: cold / reinstall / warmcache / resolve. Results CSV lands in `-BenchRoot`.

## Gotchas
- Install state lives ONLY inside the mounts (per-dir `.forest-receipt` files); nothing is written to the project root besides forest.json/forest-lock.json. Deleting a package dir deletes its receipt with it; `install --force` reinstalls everything.
- The default mount's location follows forest.json's `root`: manifests with a nested root (package authoring) install to `<root-parent>/Packages`; root-less manifests (projects) keep `./Packages`. forest-lock.json always stays at the manifest dir.
- A mount's top level is forest's alone: anything that isn't a planned package is removed on install, files and `_`-prefixed dirs included, so a Wally `_Index` and Wally's link modules go on the first install (reported in one line). Only `.` entries are never touched. Aliases still can't start with `_` or `.` because the receipt scan and type pass skip those names. This is why mounts may never nest or hold the root file, why `mount create` refuses folders with foreign files, and why install refuses the same for a folder forest never installed into (no receipted package at its top level: a mount declared by hand, or a `packagesDir` pointed at a source folder). The default mount's path (`root` parent + `packagesDir`) must stay inside the project, like every mount path.
- Symlinked/junction dirs in the mount are never descended into or deleted-through: the receipt scan and type-relink walk skip them, prune and slot-clearing remove the LINK only (`link_overlay::remove_slot`/`remove_link_path`). This protects `forest link` targets (real source trees) from install machinery.
